PULSE round-robin reliability review

October 3, 2026 · Isolated scenario simulations

The 32-player mixed-doubles case improved from a median 74.23 seconds to 0.29 seconds locally. Equal game counts, valid mixed teams, deterministic results, and partner-repeat checks pass. These measurements exclude production network latency.

Failures reproduced and fixed

  • Exponential mixed-team assignment: replaced with exact polynomial-time assignment, checked against 112 exhaustive optimization cases. Ordinary pairing now caches costs and reconstructs one solution.
  • First score created an approved match before its four participants existed, leaving immediate ratings and totals stale. Approval now happens after participant insertion in the same transaction.
  • The general 30-second duplicate detector blocked identical scores on different round-robin courts. Round robins now use their locked schedule row and linked match ID for duplicate prevention.
  • Score writes accepted abandoned, voided, and superseded matches. Server checks now reject these states, validate scores, enforce MFA, and check the schedule version for current clients.
  • Score saves used the opposite lock order from roster updates. Both now lock the event before schedule rows.
  • Event completion used several client writes. One server transaction now checks the latest schedule, backfills legacy scores, completes the event, and records its audit, with rollback on failure.
  • Score-editor failures now preserve input and allow retry without an unhandled rejection. The editor also honors the database win-by-two rule and excludes abandoned matches.
  • Activity history is loaded when opened, removing two unnecessary reads from initial event loading.

Scenario coverage

  • Planner matrix: 4 to 81 players, 1 to 16 courts, open and mixed formats, uneven rosters, equal games, rests, deterministic seeds, and partnership quality.
  • Existing 360-case equal-game matrix plus late arrivals, substitutions, departures, court changes, mixed-roster constraints, and protected rounds.
  • Full 22-player event with two Round 3 substitutions, two later departures, scores and repeated saves throughout eight resulting rounds, advancement, completion, and player-history reconciliation.
  • Ranked, guest, and unranked results; corrections; stale screens; duplicate requests; permission denial; invalid scores; partial completion; and injected audit failures with rollback.
  • Browser fixture with 150 ms simulated request delay: saved scores, updated standings, and advancement verified. Component regressions cover failed-save recovery.

Repeat the checks

npm run test:round-robin runs the focused suite. npm run benchmark:round-robin reruns timing scenarios and writes JSON under .qa-cache/. Raw measurements for this review are in measurements.json.

Limits

  • Local CPU and in-process PostgreSQL timings exclude internet latency and production load.
  • Three planner seeds per case; SQL sample counts vary by action.
  • PGlite serializes requests; stale-version and transaction rollback tests do not replace multi-device load testing.
  • No synthetic events or scores were written to production; existing historical ratings were not recalculated.
  • No finite simulation covers every possible scenario. Multi-device production latency, realtime connection loss, and large historical rating replays still require environment-specific load measurement.
